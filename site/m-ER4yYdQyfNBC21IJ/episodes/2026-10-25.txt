Okay, something you've been learning. Remember wiring up the memo, where a push makes the audio and updates the feed on its own? Here's what's actually happening when you push.

GitHub Actions is a set of instructions that lives in the repo, in a small file that says, when this happens, do these steps. The "when" is the trigger. For the memo, the trigger is a push to main.

When that push lands, GitHub spins up a fresh computer just for this job. It's blank. It clones the repo, installs whatever the steps need, and runs them in order. For the memo, that means reading the script, sending it to the voice, and turning the result into an audio file. Then that computer gets thrown away. Nothing on it survives, which is why every run starts from scratch and why anything you want to keep has to be saved somewhere on purpose.

That's where Pages comes in. Pages is plain static hosting. It doesn't run code when someone visits. It just hands out files, like the audio and the feed, exactly as they were left. So the split is simple. Actions does the work once, at push time. Pages just serves the finished files, all day, to anyone who asks.
