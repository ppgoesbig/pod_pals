# Learning
Okay, something you've been learning. Remember wiring up the memo so a push renders the audio and updates the feed? Today's what actually happens in the few minutes after that push.

First, GitHub hands the job to a brand new computer. Not a server that's sitting there waiting. A fresh, empty Linux machine, made just for this run, and thrown away right after. That's why the memo's recipe installs the audio tool from scratch every single morning. Nothing carries over from yesterday.

Second, the key. The voice service key is stored as a secret. The machine can use it, but if it ever shows up in the log, GitHub blanks it out with stars. And the recipe checks the key is there before doing any real work, so a missing key fails fast, not halfway through.

Third, a line up. The recipe says only one render runs at a time. If two pushes land close together, the second one waits its turn instead of racing the first. Otherwise two runs could both try to save the feed and trip over each other.

Last, Pages. The finished folder, the audio and the feed, gets packed up and handed to GitHub Pages. Pages is just a file host. No code runs there. It serves copies through servers all over the world, and those copies can hang on for a few minutes. So a new episode can be live and still not show up right away.
